# CoinFT 左向剪切模板修复设计

日期：2026-09-28。状态：用户已回复“可以”批准书面设计；实施计划已保存，尚未实施或上线。

## 目标与边界

修复当前定性演示中 +X 只有中心凹陷、没有向左剪切的表现。−X 对应画面向右，+X 对应画面向左。动画仍只表示信号驱动的相对响应，不输出标定力值或真实接触形貌。

原正压动画、原趋势页面、固件、采集参数和断流恢复保持不变。允许剪切同时伴随中心凹陷；本次目标是剪切方向可见，不是人为抹掉法向响应。

## 证据与限制

- 最近 ±X 数据流均在各自约5秒窗口内正常，累计异常未增加；−X 向右由用户确认，+X 中心凹陷由用户确认。
- 以最近空载段为参考，旧模板 +X 剪切分数中位约−13，24个快照全部未达到±99的启动阈值；法向动画目标中位为1。
- 探索性新权重有方向差异，但空载和按压仍有重叠，不是可上线模型。
- 当前中心采集输出曾截断，质量过滤后仅8个完整快照；±X/空载各24个快照。真实浏览器 demoBaseline 不可读。
- 同一次持续施力的前后半段不是独立验收集；不能把它们重命名为独立复测。

相关证据位于 `.superpowers/sdd/shear-plus-x-downwards-score-comparison-20260928.json` 和 `shear-three-pose-separability-20260928.json`。

## 选定方案与替代方案

推荐方案：重算与现有前端兼容的剪切权重、正压泄漏补偿及剪切显示阈值/跨度，同时用空载和纯按压作为反例。先证明候选能分离，再上线验证。

替代方案：只降低旧阈值，改动较少，但现有数据已显示噪声、按压和弱剪切重叠，容易误触发。因此不采用直接降阈值或整体翻转符号。

## 文件范围与数据流

1. 生产配置仅允许修改 `demo_web/shear_demo_profile.json` 的 `shear` 参数及对应来源元数据。保持 version1、qualitative、−X/right 与 +X/left 约定，`normal.threshold=100`、`normal.span=600` 不变。
2. 不修改 `demo_web/surface.js`、`app.js`、HTML/CSS、趋势曲线、`coinft_demo.py`、START_DEMO、标定矩阵、IMU或Teensy/CoinFT固件。若仅配置不能通过检查，先报告，不自动扩大到识别器/渲染重构。
3. 支持工作限于当前标定目录中的采集/离线拟合工具和对应测试、证据与交接文件。优先复用 `build_qualitative_demo_profile.build_profile`，不放宽它的样本/时长/质量检查；不把不足的快照复制、补值或伪装成它要求的输入。
4. 现有前端流程不变：12路相对页面基线 → CH1–8去均值及正压补偿 → 带符号剪切分数 → 原有滤波/迟滞 → 原网格拖曳。法向仍走原有CH9–12路径，识别结果不得由用户点选方向强制生成。

## 离线与采集步骤

- 已有数据先用于问题复现和候选探索，不自动视为完整拟合输入。
- 合格拟合输入须满足原工具八种状态：press_before、press、press_after、right_before、right、right_after、left_before、left。每个窗口至少40个不同递增帧快照，首末有效快照跨度至少5秒，近期异常/饱和为0、状态live、12路有限数值、同一装配身份和帧epoch。所有窗口的主机时间和帧顺序也须跨窗口递增。
- 新采集如有需要，只通过当前唯一服务的HTTP读取，不打开第二个COM6写端、不发送i/s/tare、不复位硬件。先说明缺少的对照，并逐段等待操作者确认；不能自动连续采不同姿态。
- 有界采集按首个有效快照计时，达到5秒有效跨度和样本数后结束。完成owner预检后，在首次HTTP请求开始时设置6秒采集deadline，单次HTTP超时上限1.5秒；最后一个已开始请求可能在deadline后返回，因此请求阶段硬上限为7.5秒，不含命令启动调度时间。异常、服务epoch变化或期限内样本不足则失败并保留证据，不通过额外重试延长保持时间。
- 脚本先准备好才请求用户施力；工具返回后的第一条消息先通知松手，再做解析、统计或保存。紧凑JSON和输出预算须能保留完整采集，不再依赖截断控制台文本。
- 拟合阶段与独立验证阶段使用不同实际加载动作。独立验证不能参与权重/阈值选择；失败后若修改模型，需要新的验证动作。

## 验收条件（拟合与验证前固定）

通过真实 `surface.js` 的离线回放检查最终动画目标，而不只检查裸剪切分数。首个600ms作为过渡段单独记录，稳定段标准如下：

- 空载、纯按压：`abs(shearTarget) <= 0.05`，不得持续出现错误剪切。
- −X：至少80%的稳定快照 `shearTarget >= 0.20`，无 `shearTarget < -0.05` 的反向输出。
- +X：至少80%的稳定快照 `shearTarget <= -0.20`，无 `shearTarget > 0.05` 的反向输出。
- 合成卸载/反向回放：保留现有600ms内解除旧方向和允许反向启动的测试；不改变原滤波/迟滞。
- 对同一数据和同一页面基线，正压 `normalTarget` 与改动前逐样本一致。
- 独立现场窗口：唯一采集owner、帧/字节持续前进、聚合帧率150–250Hz；异常/饱和/解析丢弃计数无新增。实际施力姿态由用户确认，候选动画目标先用该窗口离线回放检查；上线后再逐姿态取得可见方向反馈，明确标为操作者观察，不能冒称已独立读取浏览器。
- 现有相关拟合、UI、拖曳、稳定性、串口恢复测试通过；被保护文件哈希不变。原剪切配置是本次唯一明确允许变动的生产保护项。

旧按压异常、截断和较少样本不能当作候选合格输入；它们只作诊断证据。HTTP快照不是逐帧采集时间，抖动、链路延迟和真实丢帧率未测量，不为这些指标填造PASS。

## 上线、停止与回退

候选离线检查和独立验证不通过则不上线，保留旧配置并报告缺少的数据或无法分离的证据；不得为凑通过不断降低阈值，或宣称传感器损坏。

上线前保存旧配置和哈希，以apply_patch更新新配置。配置属于静态文件，不需要重启采集服务；页面刷新后仍按原流程在明确空载下点击一次演示归零。不得在按住时刷新/归零。

上线后用户逐段确认中心按压、−X向右、+X向左以及松开回平。如出现错误方向或纯按压误触发，恢复已保存的旧配置。回退不碰固件或原趋势页。
